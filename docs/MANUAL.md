## 1. 一页看懂

工作台是装在实验服务器上的一套后台程序 + 一个只读网页面板，分两半：

| | 实验侧 | 论文侧 |
|---|---|---|
| 解决什么 | 实验跑完没记下来；想回到某次实验的代码却回不去 | 每天的新论文看不过来；不知道领域里谁在什么数据集上做到多少；想不出好 IDEA |
| 怎么做 | 守护进程在实验**启动那一刻**自动保存现场；你说"记录"时由 agent 归类 | 每天凌晨抓新论文 → 判是否属于你的方向 → 读全文速读 → 挑 ≤ 10 篇精选并写精读 → 更新结果表、地图、必读 → 推进研究线 → 08:30 推送 |
| 你要做什么 | 照常跑实验（输出重定向到日志）；想记录时对 agent 说"记录" | 早上看 Telegram，在面板里读；觉得好或烂就告诉 agent 打分 |

**你不需要敲命令。** 所有反馈都对 Claude / codex 说，agent 调用 `wb` 命令写入。面板只读，不能在网页上改任何东西。

**它不会做的事：**
- 不改你的代码、不切你的分支、不碰你仓库的 `.git`（代码快照存在工作台自己的仓库里）。
- 不删除任何实验产物（除非你明确说"不要了"）。
- 告诉过你的 IDEA，只有你明确说删才删。
- 画像（研究方向、口味）的修改：你亲口说出的口味直接写入；由评价自动推出的修改要先给你看、你确认才生效，旧版本都留底。

## 2. 整体结构

```
                 ┌──────────── 实验服务器 ────────────────────────────────────────┐
你跑实验 ──────▶ │ wbd 守护进程（每分钟由 cron 保活，每 2 秒扫一次进程）            │
                 │   └─ 抓现场 → $WB_HOME/runs/ + snapshots.git                     │
                 │                                                                  │
外部论文源 ────▶ │ 每日流程 wb daily run（01:00）→ 论文库 / 结果表 / 地图 / IDEA    │
arXiv、HF、S2、  │ 自动补跑 wb daily resume（每 30 分钟）                            │
GitHub、HN       │ 推送 wb daily push（08:30）──────────────────────────▶ Telegram  │
                 │                                                                  │
                 │ 只读面板（Docker，FastAPI，端口 8765）+ 只读 MCP（/mcp）          │
                 └──────────────────────────────────────────────────────────────────┘
你 ◀──── 读面板、看推送；对 agent 说话 ──▶ agent 调 wb 命令写入
```

**四个地方，各管一件事：**

| 位置 | 放什么 | 进不进 GitHub |
|---|---|---|
| 仓库（服务器上的部署目录） | 代码、面板、agent 规则与 skill、设计文档 | 是（GitHub 是唯一来源） |
| `$WB_HOME`（数据目录） | Run、论文库、地图、IDEA、报告，以及**你的个人配置**（`config.json`、`registry/field.json`、`registry/seeds.json`） | 否 |
| `$WB_HOME/secrets/`（权限 600） | 批量模型 key、额度管理端 key | 否 |
| `panel/.env` | 面板容器的 uid、路径、端口 | 否 |

**两类模型：**
- **批量模型**（Gemini，经 GPT-Load 网关）：相关性判定、速读、精读、结果表整理、中稿评估、口味打分、地图每日归类与叙述、研究主题、周报。量大、便宜。
- **codex**（`codex exec`，用 ChatGPT 订阅额度）：地图重组、构思、独立审稿、研究线每天的一步、问题文档与 IDEA 文档。少而重，额度紧。

## 3. 时间表：系统每天自己在做什么

时间均为北京时间。

| 时间 | 发生什么 | 在面板哪里看 |
|---|---|---|
| 全天，每 2 秒 | 守护进程检查新启动的实验，**启动那一刻**保存现场 | 待认领 |
| 每天 01:00 | 每日流程，13 步依次执行（见第 5 节） | 今日论文 → 页面底部"流程明细" |
| 每天 08:30 | Telegram 推送当期 | — |
| 每 30 分钟 | 自动补跑：额度恢复后接着跑暂停 / 失败的步骤；补好了推"🔄 更新"；没有欠账时按预算续跑历史回填 | 今日论文 → 流程明细 |
| 每周一 | 广撒网构思（第 11 节）；出上周周报 | IDEA、报告 |
| 每月 1 日 | 出上月月报 | 报告 |
| 每周最多一次 | 领域地图重组（其余日子只把新论文归进已有类别） | 地图 |
| 每 30 天 | 研究主题表重新提议一次（保留稳定的 id） | 地图 → 热点 |

**一期 = 一天。** 08:30 推第一版；当天有新进展（精读补好了、被录用了、放出代码了、重新精选了）就更新同一期，不另开一期。

## 4. 实验侧：自动记录实验

### 4.1 自动抓现场（ADR-0001～0009）

守护进程 `wbd` 每 2 秒扫一次**当前用户**的进程。候选是：python 进程且工作目录 / 脚本在 `watch_roots`（你配置的实验根目录）下，或任何用了 GPU 的进程。

- 候选活过一个 tick 就拍代码快照（`python -c` 之类的短命进程不浪费快照）；
- 用了 GPU 或活过 60 秒就成为一个 **Run**。

每个 Run 在**启动那一刻**保存：

| 内容 | 说明 |
|---|---|
| 代码 | 含未提交改动和 untracked 文件。存在集中的 bare 仓库 `$WB_HOME/snapshots.git`，不碰你自己的 `.git`、不切分支、不动 stash；git 自动去重 |
| 命令 | 完整命令行、工作目录 |
| 环境 | 环境变量（密钥类自动脱敏）、`requirements.txt`、GPU 采样 |
| 日志 | 进程输出重定向到的文件 |
| 产物 | checkpoint / 预测等的只读副本（> 50GB 或磁盘紧张时只做硬链接），永久保留 |
| 对话关联 | 找到启动这个实验的那段 codex / Claude 对话（读 `~/.codex/sessions`、`~/.claude/projects`，只看启动前 12 小时内的） |

**你唯一要配合的**：启动实验时把输出重定向到日志文件，例如 `nohup python train.py --seed 0 > logs/seed0.log 2>&1 &`。agent 规则里已经写了这一条。

### 4.2 层级（ADR-0010）

```
项目 Project = 你自己要写的一篇论文（手动创建；别人论文的代码只是 baseline）
└─ 实验 = 论文里的一个 claim
   └─ 配置组 Variant = 方法 × 参数 × 任务，只差种子；均值 ± 标准差在这层算
      └─ Run = 一次运行（守护进程自动抓到，认领前在"待认领"里）
```

### 4.3 认领："记录"（ADR-0009）

你说"记录"时，agent：`wb inbox` 找到 Run → `wb context <RUN>` 从启动它的对话里起草"目的" → 跟你确认归属 → `wb adopt <RUN> -v <配置组> -p "<目的>"`。

认领后，同一配置组里不同种子自动算**均值 ± 标准差**；组内代码 / 参数不一致（除了种子字段）会给出警告。

不是实验的进程（调试、下载、服务）说"这个不是实验"，agent 执行 `wb ignore <RUN>`：只是不再出现在待认领里，记录和产物都保留。

### 4.4 还原与对比

- `wb restore <RUN> [目录]`：生成一个独立目录，代码、依赖清单、重跑脚本齐全，不碰当前工作区。git 仓库会带上历史，`git status` 就是当时的未提交改动。
- `wb diff <RUN> [<RUN2>]`：两次实验之间的代码差异，或和现在的工作区比。
- 复现对比（ADR-0023）：`wb repro ref <配置组>` 记录论文报告的数字，`wb repro check` 和我们的均值 ± 标准差比，容差内算"已复现"。

## 5. 论文侧：每日论文流程

每天 01:00 由 cron 启动 `wb daily run`，13 步依次执行。每一步的状态（ok / paused / failed）、耗时和结果摘要都记在当期里，面板"今日论文"底部的"流程明细"能看到。

| # | 步骤 | 做什么 | 用谁 |
|---|---|---|---|
| 1 | harvest 抓取 | arXiv（研究方向的每个关键词 × 指定分类，近 4 天新提交）、HF Daily Papers、引用了种子论文的新论文（Semantic Scholar）。去重顺序：arXiv ID > DOI > 标题 | — |
| 2 | judge 相关性判定 | 每批 30 篇标题 + 摘要，只判"是否属于研究方向"，不评好坏。你标过"不相关"的论文作为反例写进提示 | 批量模型 |
| 3 | read 速读 | 属于方向的每篇读全文：中文标题、一句话、问题 / 方法 / 实验与结果 / 局限、实验设置、维度标签、**原文数字抽取**、评测规模、质量分。所有数字只能来自原文，不确定就不写 | 批量模型 |
| 4 | results 结果表 | 新数据集名归类、补评测规模、核对方法名、核实代码、重建结果表索引（第 8 节） | 批量模型 + GitHub API |
| 5 | attention 关注度 | HF 点赞、Hacker News 讨论、录用会议与引用数（S2） | — |
| 6 | choose 精选 | ≤ 10 篇（第 6 节） | 批量模型 |
| 7 | repos 新仓库 | 方向内新出现的 GitHub 仓库，过口味过滤 | 批量模型 |
| 8 | hf HF Daily 栏 | 近 7 天上过 HF Daily、属于方向的论文按点赞取前 5，过口味过滤 | 批量模型 |
| 9 | explain 精读 | 每篇精选写 8 步精读 HTML（paper-explainer） | 批量模型（默认）或 codex |
| 10 | map 领域地图 | 新论文归类、打研究主题、更新发展史 / 热点 / 评测与基线 / 空白；每周最多重组一次分类 | 批量模型；重组用 codex |
| 11 | ideate 构思 | 推进研究线各一步；周一另做广撒网构思（第 11 节） | codex |
| 12 | reports 报告 | 热点榜（近 72 小时）、必读清单刷新；周一周报、1 日月报 | 批量模型 |
| 13 | profile 画像 | 新评价攒够 3 条时起草画像修改（等你确认） | 批量模型 |

**收录 vs 精选：** 收录只判"是否属于方向"，属于的每篇都有速读，都进论文库、结果表、地图；精选是从中挑出值得你今天读的，每篇另有精读。

**你自己提供论文**（ADR-0033）：对 agent 说"把这篇加进来"（arXiv 号、链接、标题或服务器上的 PDF），执行 `wb paper add`，直接进库并立刻速读，可选设为种子、顺带精读。你提供的论文不进每日精选（你已经知道了），但参与地图、结果表、构思和画像。

**回填：** 首次安装时 `wb backfill` 回填近 12 个月的 arXiv 和引用 baseline 的论文；之后每 30 分钟的自动补跑在额度有富余时按预算续跑。顶会顶刊论文另有检索（第 9 节），所以论文库对近 12 个月是全量，更早的只有顶会顶刊论文。

## 6. 精选是怎么挑出来的

（ADR-0020、0027、0036、0037、0039）

```
近 90 天属于方向、质量 ≥ 6 的候选
  │ ① 原分数 = 质量 + 关注度 + 与种子的引用关系 + 有代码 / 已录用
  ▼
取原分数前若干篇
  │ ② 硬门槛：方法类论文必须和"领域常用方法"至少比过一个，否则直接出局
  ▼
  │ ③ 一次批量模型调用，对每篇给出：
  │     中稿评估 accept（1–10，按 CCF-A 主会审稿标准，依据是结果表统计出的证据）
  │     口味分 like（0–1，对照你的评价与画像里的口味）
  │   accept < 5 出局；like < 0.4 出局
  ▼
总分 = 0.3 × 原分数 + 0.4 × 中稿评估 + 0.3 × 口味分     （没有口味时 0.4 × 原分数 + 0.6 × 中稿评估）
  │
  ▼
按总分排序，最多 10 篇；达标的不够 10 篇就少推
```

**领域常用方法**：被论文库里 ≥ 5 篇论文当作对比方法的方法，去掉通用做法（CoT、ReAct、Debate……）、模型名（GPT-4o……）和现成 agent 工具（Claude Code、Codex……）。也可以在画像里用 `selection.standard_baselines` 直接指定（会覆盖自动计算）。

**推送和面板里会写出依据**：对比了哪些常用方法、中稿评估几分、为什么合你口味。

**额度不够时**：中稿评估 / 口味打分做不成，就先按原排序出刊，同时记下"待重新精选"；额度恢复后由自动补跑按完整规则重选，原精选留底，补精读并推送更新。

**手动重新精选**：`wb daily repick --reason "…" --force`（例如你改了口味后让 agent 重排本期）。

**HF Daily 栏**单独一栏，不算精选：方向不放宽（必须属于你的方向），但不过 baseline 硬门槛，所以会写明"有没有和领域常用方法比较"；你评过 ≤ 2 分的、重新精选时被换掉的不推。

## 7. 评价、口味与画像

（ADR-0015、0033、0036、0039）

**画像**存在 `$WB_HOME/registry/field.json`，包括：
- 研究方向：名称、描述、子主题、arXiv 检索词与分类、维度（优化对象 / 搜索方式 / 粒度 / 论文类型）；
- 精选参数：每天最多几篇、质量门槛、候选窗口、领域常用方法名单；
- **口味**：`taste.likes`（喜欢什么）、`taste.dislikes`（不喜欢什么）；
- 构思参数：研究线上限、你配置的工作区与结果目录。

**评价**：对 agent 说"这篇给 1 分，理由是……"，执行 `wb paper rate <论文> <1-5> --note "理由"`。1 很差 · 2 差 · 3 一般 · 4 好 · 5 很好。论文页有"我的评价"区，论文库可按评价筛选 / 排序。

**评价和口味怎么起作用：**

| 地方 | 作用 |
|---|---|
| 每日精选 | 口味分参与排序，< 0.4 不推（第 6 节） |
| HF Daily 栏、新仓库、热点、必读里的"值得读" | 过口味过滤，不合口味的不推，推送 / 面板写出理由 |
| IDEA | 不合口味的不告知你（保留在隐藏区） |
| 构思 | 评价 ≤ 2 的论文不作为方法依据 |
| 画像 | 新评价攒够 3 条，每日流程自动起草画像修改，推送里提示；你确认后 `wb field apply` 才写入 |

"不相关"和低评价不同：**不相关**是"这篇不属于我的方向"（以后少收类似的）；**低评价**是"属于方向，但做得不好 / 不合口味"。

修改画像前自动留底（`registry/field.history/`）。

## 8. 跨论文结果表

（ADR-0027、0034、0035）回答"同一个数据集、同一个指标下，各方法报告了多少"。

**组织方式**：任务类别（数学 / 代码生成 / 问答 / 知识与综合推理 / 智能体 / 其它）→ 每个数据集一张表，行 = 方法，列 = 指标，最好加粗、第二下划线。**不按 backbone 拆**（复现时你自己跑），backbone 悬停可见。

**每个数字都带：**

| 标注 | 含义 |
|---|---|
| 评测规模 | **全量**（完整划分）/ **子集**（随机抽样或选了一部分，带题数）/ **未注明**（原文没写）。从原文抽取，不靠猜；题数和官方全量都知道时按数字判定（论文常把过滤后的集合也叫 test set） |
| 代码 | 这个方法自己论文的代码是否真的开源：已开源 / 只有 README / 空仓库 / 匿名审稿仓库 / 链接失效 / 未开源。GitHub 逐个查仓库内容；已开源的每 30 天复查，其余每 7 天复查 |
| 方法名 | 按原文核对过：速读抽取的名字先机械检查是否出现在原文，再由模型对照原文段落核对准确写法、是不是本文提出的方法。更正后的名字悬停可见原抽取写法；原文找不到的不进表 |
| 出处 | 点回论文与表号；是原论文报告还是别人转引 |

**同一方法在同一格有多处报告时**：优先它自己的论文，其次全量评测，再次数值最高的那条；转引取中位数；其余放悬停提示。只汇总，不改写数字（唯一换算：同一列大多是百分数而这一条写成 0.xx 时乘 100，并注明）。百分比类指标超出 0–100 的不进表。

**数据集归一**：同一数据集的不同写法合并（"GPQA-Diamond" / "GPQA Diamond"），不同版本分开（AIME 2024 / 2025，SWE-bench / SWE-bench Verified），子集写法（"MATH (lv5*)"）并到父数据集并标为子集。常见数据集写在代码里（含官方全量规模），其余由模型归类一次，存 `registry/datasets.json`。

命令：`wb results` 列数据集；`wb results <数据集>` 看报告；`wb results refresh` 手动刷新。

## 9. 顶会顶刊必读

（ADR-0040）面板"必读"页，按首次公开时间排序。

**算顶会顶刊的**：CCF-A 会议与期刊（含 TPAMI）、ICLR（CCF 未列，单独标注）、Nature / Science 及子刊。**不算**：研讨会（workshop）、Findings、demo / tutorial / 博士论坛等。ACL 系列靠 DOI 区分主会和 Findings。会议年份只用录用信息里写明的，不拿 arXiv 年份代替。

**来源**：论文库只回填了近 12 个月的 arXiv，经典工作大多不在库里，所以另用 Semantic Scholar 按方向关键词 × 顶会顶刊（2023 年起）检索，新论文进库走相关性判定与速读（不进每日精选）。录用信息综合 S2、arXiv 评论、速读里作者自称的会议。

**必读** = 属于方向 + 顶会顶刊 + 至少一条：
- 种子论文；
- 领域常用方法的原论文；
- 被论文库里 ≥ 3 篇论文当作对比方法；
- 高引用（发表满一年 ≥ 100，不满一年 ≥ 40），且过口味过滤。

其余顶会顶刊论文是**值得读**，过口味过滤。命令：`wb topvenue run | ls [--worth]`。

## 10. 领域地图

（ADR-0021、0041）面板"地图"页分两部分。

**A. 看懂领域**（每天更新，统计部分可复核，叙述部分每条都要引用论文 id 或统计数字）：

| 部分 | 内容 |
|---|---|
| 发展史 | 各阶段的主线 + 里程碑论文 + 每个里程碑对比过哪些更早的里程碑 |
| 研究热点变化 | 15 个研究主题按半年的**占比**（不看篇数，因为早期只收了顶会论文）与近半年变化；早期样本少的时间段单独标注 |
| 评测与基线 | 现在要比的 baseline、每年常用的 benchmark、各 benchmark 的饱和度（看前 10% 成绩，样本 ≥ 8 才算） |
| 空白与其它发现 | 主题 × 搜索方式矩阵里的空格 + 有依据的发现 |

**研究主题**：比维度标签更细的热点（如"查询自适应路由与分级编排""通信图剪枝与 Token 效率优化"），由模型从按时间分层抽样的论文里提出 12–20 个，每篇论文打 1–2 个，新论文每天增量打；主题表每 30 天重新提议一次，存 `registry/themes.json`，你可以改。

**B. 分类**（Related Work 文体）：一个主分类，每类写核心思路、代表工作（优先里程碑，再加近半年代表作）、**这一类没考虑到什么**（找问题的入口）。每天把新论文归进已有类别；每周最多由 codex 重组一次，版本全留（`map/v<N>.json`）。`wb map rebuild --fresh` 全面重建（重新划分类别，不照搬上一版）。

## 11. 构思：研究线与 IDEA

（ADR-0018、0024、0025、0042、0043）

### 11.1 研究线：少而深

一条**研究线** = 一个具体研究问题，持续多天推进。**同时最多 3 条。**

每天每条线由 codex 推进**一步**，步骤类型包括：精读关键论文、查新（联网查有没有人做过）、分析失败样本、形式化方法、设计最小实验、修改 IDEA 草稿。发现和证据记在线上（面板 IDEA 页能看到每一步的研究记录）。

草稿成熟（codex 判断 ready_for_review）才交**独立审稿**：
- 通过 → 成为正式 IDEA，写问题文档与 IDEA 文档，推送告诉你；
- 没通过 → 按审稿意见继续推进；
- 审稿 3 次仍不过 → 搁置，写明原因。

**研究线从哪来**（优先级从高到低）：

| 来源 | 怎么建 |
|---|---|
| **mine** 你自己的研究问题 | 对 agent 说"加一条研究线：……"，执行 `wb thread add "问题" --mine`。**最优先** |
| **repro** 复现与 bad case | 只有你在画像里**显式配置**了结果目录（`ideation.badcase_roots`）才会自动建一条，分析各方法的逐样本预测与评测。不会从其它目录推断 |
| **open** 领域开放问题 | 以往接近通过的候选（没被否决、均分 ≥ 6，已有审稿意见）优先，其次是地图里各类"没考虑到什么" |

有空位时按这个优先级补。你可以随时：`wb thread park <id> --reason`（搁置）、`resume`（恢复）、`drop --reason`（放弃）。

### 11.2 每周广撒网

每周一另做一次广撒网构思：codex 根据论文库、地图、结果表、以往被拒的审稿意见想多个候选 IDEA，每个都针对一个有真实证据的问题。提示里写明四类常见被拒原因（撞了已有工作、证据错、问题不真实、贡献不够）的对应要求。接近通过的（没被否决、均分 ≥ 6）按审稿意见修改一轮、换审稿人重评；仍不过的进研究线候选。

### 11.3 独立审稿

审稿人是另一个 codex 会话，**联网查新**，按 idea-reviewer skill 打分：
- **两票否决**：新颖性（已有人做过）、问题真实性（问题不存在或证据不成立），任一否决即不通过；
- 其余维度均分 **≥ 7** 才通过；
- 再过一次口味过滤，不合口味的不告诉你（保留在隐藏区）。

### 11.4 IDEA 的生命周期

```
候选（ideas/.hidden/，没通过的留着用于去重）
  └─ 通过审稿 → IDEA（ideas/<id>/：问题文档 + IDEA 文档 + 审稿意见 + 查新记录）
        ├─ wb idea verify   开始验证
        ├─ wb idea promote  升级为某个项目的 claim
        ├─ wb idea abandon  放弃
        └─ wb idea delete   删除（只在你明确要求时；移到 ideas/.deleted/，可恢复）
```

大多数时候对 agent 说就行，下表是 agent 会执行的命令，供你核对。所有命令都支持 `--json`。

## 15. 模型、额度与自动补跑

（ADR-0030、0031、0032）

| | 批量模型（Gemini） | codex |
|---|---|---|
| 接入 | `$WB_HOME/secrets/llm.env`，经 GPT-Load 网关 | 服务器上已登录的 codex，`config.json` 的 `codex` 可改模型 / provider |
| 额度来源 | 读 GPT-Load 管理端的真实额度（`secrets/quota.env`）：分组里每个凭据的 5h / 7d 剩余、重置时间、冷却 | ChatGPT 订阅额度 |
| 用于 | 判定、速读、精读、结果表、中稿评估、口味、地图归类与叙述、主题、报告 | 地图重组、构思、审稿、研究线、问题 / IDEA 文档 |

**额度用完不会白白重试：**
- 批量模型：分组里**任一凭据**可用就继续；全部不可用时相关步骤标"暂停"，写明预计恢复时间。窗口的重置时间已过就当作已恢复（GPT-Load 只在有请求经过时刷新观测，旧快照不作数）。
- codex：用完时构思 / 研究线标"暂停"。
- 每 30 分钟的自动补跑：先做排队的重新精选，再从第一个暂停 / 失败的步骤起往后重跑（**不重跑抓取**），补好了推"🔄 更新"；没有欠账时按预算续跑历史回填。

随时 `wb daily status` 看额度和暂停原因；用量记录在 `reports/llm_usage.jsonl`、`reports/codex_usage.jsonl`。

## 16. 它读什么、不读什么（数据边界）

这一节写清楚工作台会碰你服务器上的哪些东西。

| 读什么 | 谁读 | 为什么 |
|---|---|---|
| `watch_roots` 下启动的进程（以及任何用 GPU 的进程）的代码目录、命令、环境、日志、产物 | 守护进程 | 自动抓现场。只在进程启动时拍快照，不改原目录 |
| `~/.codex/sessions`、`~/.claude/projects` 里启动前 12 小时内的对话 | 守护进程 / `wb context` | 把 Run 和启动它的对话关联起来，起草"目的" |
| 论文（arXiv、HF、S2、GitHub、HN 的公开数据） | 每日流程 | 论文侧的全部功能 |
| 你**显式配置**的 `ideation.workspace`、`ideation.badcase_roots` | 研究线 | 分析你的 bad case。**不配置就不读**；不会从 `baseline_dir` 或其它目录推断（v0.11.0 修复） |
| `config.json` 的 `baseline_dir` | 只用于 agent 规则 | 复现论文时官方代码放哪里（ADR-0023）。不作为研究对象 |

**不读：** 你没配置的目录、你的私有评测结果、你的个人项目代码（除非它在 `watch_roots` 下作为实验被启动，此时只做快照，不拿去构思）。

构思（研究线、广撒网）的材料是：论文库、地图、结果表、以往审稿意见、你的评价、你显式配置的结果目录，以及**你认领过的** Run。守护进程抓到但没认领的进程（调试脚本、下载命令等）不算你的实验，不进构思材料（v0.11.0 之后修复；之前会把最近 60 个 Run 都给构思）。

## 19. 维护、发版、排障

详见 [`MAINTAINING.md`](../MAINTAINING.md)，要点：

- **GitHub 是唯一来源**。所有改动走：开分支 → 改代码 + 测试（有新决策写 ADR）→ PR → CI 通过 → 合并 → `scripts/deploy.sh`。部署前有未提交改动会直接拒绝，保证服务器上跑的就是 GitHub 上的 `main`。
- **发版**：你说"发 vX.Y.Z"时，更新 `CHANGELOG.md` 与版本号 → PR → CI → 合并 → 等 `main` 的 CI 通过 → 打 tag、建 GitHub Release → 部署。
- **个人信息**（路径、IP、账号、项目名）只写在数据目录或 `.env` 里，不进仓库；CI 会扫描密钥形态的字符串。

| 现象 | 先看 |
|---|---|
| 实验没被抓到 | `wb doctor`；`$WB_HOME/daemon/daemon.log` |
| 推送没来 / 内容不全 | `wb daily status`；`reports/daily/<日期>.log`；`daemon/daily-cron.log` |
| 某一步一直暂停 | `wb daily status` 第二行（额度）；`reports/llm_block.json`、`codex_block.json` |
| 面板打不开 | `docker logs workbench-panel` |

## 20. 已知局限

- 直接输出到终端（不重定向）的日志无法事后捕获。
- 退出码通常拿不到（守护进程不是父进程），按日志推断。
- 轮询有约 2 秒延迟：进程启动后 2 秒内代码就被改会漏掉（面板上"迟到抓取"会标出来）。
- 产物超大时只做硬链接，挡不住"原地覆盖写"。
- 守护进程按规则抓**所有**符合条件的进程，包括调试脚本、下载命令；不是实验的需要 `wb ignore`。
- 抓取一步失败（例如 arXiv 限流 429）时，自动补跑不会重跑抓取，当天的新论文要等第二天的抓取窗口（覆盖近 4 天）补上。
- 服务器停机期间 cron 不跑，那一天没有当期。
- 结果表、方法名、评测规模都来自模型对原文的抽取，有核对但不保证 100% 正确；每个数字都能点回原文表号核实。
- 早期（12 个月前）的论文只收了顶会顶刊，热点趋势看占比，早期样本少。
