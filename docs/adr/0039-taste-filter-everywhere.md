# ADR-0039：所有推荐都过口味过滤

- 状态：已接受（扩展 ADR-0036）
- 日期：2026-10-13

## 背景
口味（画像里的喜欢 / 不喜欢 + 本人评价与理由）原来只用于每日精选的排序。HF Daily 栏上线后第一天就出现了本人明确不喜欢的那类论文
（主要贡献是省 token 的 SLA），本人要求"给所有的推荐都加上"口味过滤。

## 决策
1. `taste.screen()` / `taste.keep()`：一次批量模型调用，对一批条目（论文 / 代码仓库 / 研究想法）给"会不会喜欢"（0–1）和一句理由；
   低于 `selection.min_like`（默认 0.4）的去掉，理由写回条目并在推送 / 面板里显示。
2. 用在所有推荐上：
   - 每日精选：原来口味只占排序的 30%，现在口味分低于门槛的直接不进；
   - HF Daily 栏、新仓库、热点：先按原规则选，再过口味过滤；
   - IDEA：评审通过但不合口味的不告知，和没通过评审的放在一起（verdict = taste），写明理由，本人可以让 agent 翻出来。
3. 画像里没有口味且评价少于 3 条时不过滤；模型不可用时照常展示、不过滤（不让推送空着）。每日精选的重新精选仍然要求真的做了（ADR-0036 补充）。

## 后果
- 每天多 3–4 次小的批量模型调用（HF 栏、新仓库、热点、IDEA 各一次）。
- 推得更少但更合口味；被口味挡掉的 IDEA 不会丢，只是不主动告知。
