# ADR-0037：精选加硬门槛与中稿评估

- 状态：已接受（修改 ADR-0020 / 0027 的精选打分，补充 ADR-0036）
- 日期：2026-10-12

## 背景
本人反馈 2026-10-12 的 10 篇精选"不像能中会议的，baseline 都没有"。核查：10 篇里 9 篇没有和领域常用方法（AFlow、ADAS、MaAS、G-Designer、AgentPrune……）
正面比较——只和自己的变体、Claude Code / Codex 这类工具或模型比，或者只在自建 benchmark、少量抽样上评测。
原因是精选分数里权重最大的"质量分"来自速读模型的自评，几乎每篇都给 8/8/8，评语也偏宽松（"实验异常扎实"），区分不出好坏。

## 决策
1. **领域常用方法 / 常用 benchmark 从论文库统计**（`rigor.py`）：被 ≥ 5 篇论文当作对比方法的方法，去掉通用做法（CoT、ReAct、Debate……）、
   模型名、现成 agent 工具（Claude Code、Codex……）；被 ≥ 5 篇论文用过的数据集。画像里 `selection.standard_baselines` 可以直接指定名单（覆盖统计结果）。
2. **硬门槛**：方法类论文一个领域常用方法都没比 → 不进精选（`selection.require_std_baselines`，默认开）。
3. **中稿评估**：过门槛的前 30 篇交给批量模型，按 CCF-A 主会审稿标准打 1–10，证据是从结果表统计出来的那一行
   （对比了哪些常用方法、用了哪些常用 / 自建 benchmark、子集占比、有没有消融），明确的扣分规则写在提示里；低于 `selection.min_accept`（默认 5）的不进精选。
   同一次调用给出口味分（ADR-0036）。总分 = 0.3 原分数 + 0.4 中稿评估 + 0.3 口味（没有口味时 0.4 原分数 + 0.6 中稿评估）。
4. 达标的不足 10 篇就少推，不凑数。面板和推送写出证据（对比了哪些常用方法、常用 benchmark、中稿评估）。
5. 批量模型不可用时，每日流程只用硬门槛 + 原分数；本人要求的重新精选等额度恢复再做（ADR-0036 补充）。

## 后果
- 每天能推的论文变少，但每篇都至少和一个领域常用方法比过；harness / prompt 优化这类相邻方向的论文若只和工具比，会被挡掉。
- "领域常用方法"名单决定门槛松紧，本人可以随时改。
