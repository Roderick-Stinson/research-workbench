# ADR-0009：后台自动抓现场 + 说"记录"时认领补全

- 状态：已接受
- 日期：2026-10-11
- 修订：取代 ADR-0002 里"记录器写进脚本"和 `wb run` 前缀的做法。本人要求"平时正常跑，说记录时才记录"。

## 背景
- 本人不想改变启动方式（不加前缀、不改代码）。
- 但如果等说"记录"时才拍快照，代码可能已经被 agent 改过，违反 ADR-0003。
- 目的（Purpose）无法从进程本身得到。实验室服务器上有 codex 会话 128 个（`~/.codex/sessions`）、cc 会话 22 个（`~/.claude/projects`），
  里面有完整的用户发言、agent 执行的命令和时间戳。

## 决策
1. **抓现场（自动、无感）**：实验室服务器上常驻一个轻量守护进程（用户态 systemd 服务或 docker 容器），轮询发现 `<watch_root>/**` 下新启动的实验进程，
   **立刻**保存：代码快照（隐藏 git ref）、完整命令行、cwd、相关环境变量（脱敏）、pip freeze、配置文件内容、stdout/stderr 重定向目标、GPU。
   进程结束时补记：退出码、耗时、日志尾部。
2. **关联对话**：沿着进程的父进程链找 codex / claude 进程；找不到（nohup / setsid / tmux 会断开父子关系）时，
   按"命令字符串 + 时间"去会话记录里匹配。关联结果附上置信度。
3. **认领（说"记录"时）**：由 agent（通过实验室服务器上的 skill / CLAUDE.md / AGENTS.md）完成：
   找到对应的 Run → 从关联的对话里**起草**目的 → 本人确认 → 填写实验名（ADR-0005）、结果、结论。
4. 脚本启动的正式实验：从脚本的 `# purpose:` 注释读取，或者在认领时询问。
5. 没认领的 Run 进入面板的"待认领"列表，不会丢失，也不会被删除。

## 已知局限
- 直接输出到 tmux 终端的 stdout 无法事后捕获 → 约定 agent 启动实验时一律重定向到日志文件。
- 轮询有几秒延迟，理论上进程启动后几秒内代码被改的情况会漏掉（实际中极少）。

## 实验进程的判定（Q12）
- 候选：`<watch_root>/**` 下、属于 <user> 的 python 进程（以及任何用了 GPU 的进程）。
- **发现候选时立即拍快照**（git 对象去重，开销很小）。
- 满足以下任一条件就升级为 Run：用了 GPU，或者存活超过 60 秒。
- 不满足的（短命脚本），丢掉候选快照：它不是 Run，不受 ADR-0004 约束。
- 判定宽一些：以前的 MAS / <项目 B> 实验多为调用 API、不用 GPU，必须能抓到。误抓的在"待认领"里忽略即可。
