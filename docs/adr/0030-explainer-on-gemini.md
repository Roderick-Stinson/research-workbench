# ADR-0030：8 步精读改由 Gemini 执行；codex 只做地图、构思、审稿、问题 / IDEA 文档

- 状态：已接受（取代 ADR-0020 中"精读由 codex 执行"的部分）
- 日期：2026-10-12

## 背景
2026-10-12 第一次真实运行时，codex（ChatGPT 订阅，gpt-5.6-sol / xhigh）在精读阶段额度用完（"try again at 3:16 PM"），10 篇精读全部失败。
精读是 codex 的主要用量（每天最多 10 篇，xhigh 下每篇约 7.5 分钟）。

## 决策（本人选择）
- **精读 → Gemini**（批量模型，`field.json` 的 `explainer_engine=gemini`，可切回 codex）：
  先一次调用出 hero 字段 + 提纲 + 原文参考文献列表，再 8 步**并行**各写一段（每次输出小，避开第三方网关约 280 秒的超时），
  参考文献由工作台按列表统一生成，保证引用闭合。图由模型直接写内联 SVG（数字照抄原文表格），不再跑脚本作图。
- **地图重组、构思、审稿、问题 / IDEA 文档仍由 codex 执行**（需要跑代码作图、联网查新），推理强度降为 `high`。

## 后果
- 精读不再占订阅额度；质量相对 codex xhigh 可能略弱，靠 check_html 的占位符 / 引用检查兜底，本人看过后再决定是否调整。
- codex 失败（额度 / 限流）会进入当期的告警；额度恢复后可单步重跑：`wb daily run --steps map,ideate`。
