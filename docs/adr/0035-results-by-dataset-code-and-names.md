# ADR-0035：结果表按数据集展示（不分 backbone）、核实代码是否开源、核对方法名

- 状态：已接受（部分取代 ADR-0034 第 3 条）
- 日期：2026-10-12

## 背景
ADR-0034 的论文式对比表按 分类 → backbone → 方法 × 数据集 组织，本人反馈：
1. 看起来累；backbone 不重要——要复现时自己跑，只需要知道"哪个数据集、哪个方法、在哪个指标上报告了多少"；
2. 要核实代码是否真的开源，并标出来；
3. 方法名要和论文一致（印象中有方法名被写错）。

核查时发现：抽取的方法名里有 350 / 4,230 个没有原样出现在论文里（多为把表格行列拼在一起，也有通用占位名 "Ours" / "Proposed"）；
论文给出的代码链接有的 404、有的只有 README、有的是匿名审稿仓库；另有百分比指标写成 139.6 这种明显抽错的数字。

## 决策
1. **按数据集展示**：分类 → 每个数据集一张表，行 = 方法，列 = 指标（主要的 2 个；数据集页最多 6 个），另有 评测规模 / 代码 / 数字出处 三列。
   不按 backbone 拆，backbone 放在悬停提示里。分类页只放方法最多的 15 个数据集（每张前 10 行），其余列成清单。
2. **每格取哪个数字**：方法自己的论文报告的（多条取最好）> 别的论文转引的（优先全量评测，取中位数那条——取最高值会挑出设置不同的偶然高分）。
   其余报告在悬停提示里。同一方法的不同配置并成一行（括号里的配置写在方法名下面），消融（w/o …）单独一行、默认隐藏。
3. **代码是否开源**（`codecheck.py`）：对论文 / arXiv 评论 / HF 给出的链接，GitHub 仓库查是否存在、是否为空、根目录（或链接指向的子目录）
   有没有代码文件；项目主页顺着页面上的 GitHub 链接查；匿名审稿仓库单独标出。状态：已开源 / 只有 README / 空仓库 / 匿名仓库 / 链接失效 / 未开源（没有链接）。
   GitHub API 用本机已登录的 gh（只读）。已开源的 30 天复查，其余 7 天复查。结果表"代码"列和论文页都标出来。
4. **方法名核对**（`namecheck.py`）：机械检查每个名字是否出现在原文里，再由批量模型对照原文逐个给出原文写法、是否本文方法；
   核对后原文里找不到的名字不进表，改过的名字悬停可见原抽取写法。速读提示里也要求照抄原文方法名。
5. 常见数据集的子集写法（"MATH (lv5*)"、"GAIA (Level 2)"）并到父数据集，评测规模记为子集并标出子集说明。
6. 百分比类指标（Accuracy / Pass@1 / F1 / EM / Success Rate）超出 0–100 的数字不进表。

## 后果
- 跨论文的数字更好读，但设置差异（backbone、提示、采样）被藏进了悬停提示；评测规模列和"规模不一"提示仍然在表面。
- 每日流程的"结果表"步骤多了方法名核对（新论文）和代码核实（到期的论文）；老论文的方法名核对由 resume 按回填预算补。
