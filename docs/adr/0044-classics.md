# ADR-0044：经典工作

- 状态：已接受
- 日期：2026-10-18

## 背景
本人要求加一个模块，梳理当前领域的经典工作。已有两处相关内容，都不够：
- "必读"（ADR-0040）只收顶会顶刊、按时间平铺：AutoGen（被论文库里 48 篇当作对比方法）、DyLAN（37 篇）这类没发在 CCF-A 的经典进不来，也看不出谁继承了谁。
- 地图的里程碑（ADR-0041）只是发展史叙述的一部分。

核查结果表时还发现：被对比最多的方法里，不少原论文不在库里，或者结果表没认出是哪篇（AutoGen、ADAS、DyLAN、AgentPrune、MetaGPT 都是）；
还有方法名被算错原论文的情况："Meta-Harness" 被算到一篇 2026-09 的后续论文头上（那篇的方法名核对把 Meta-Harness 列成了本文方法），
"ACE" 有 4 篇论文认领。

本人选择：经典和必读两页都保留；经典按影响力选，不限会议。

## 决策
1. **影响力门槛**（`field.json` 的 `classics`，可调）：方法被论文库里 ≥ 8 篇论文当作对比方法（只数在原论文之后或 60 天内同期发表的对比）；
   或引用 ≥ 200 且发表满一年；或种子论文 / 领域常用方法的原论文。泛称（"Ours"、"SFT"、"Full"、"Multi-Agent"……）、通用做法、模型名、工具不算方法。
2. **方法 → 原论文**：按标题核对过的优先；否则同名方法由最早认领的那篇论文算；有 ≥ 3 篇论文认领的是重名，不按名字认。
3. **找原论文**：被大量对比、但认不出原论文的方法，由批量模型判断是否是具体方法并给出原论文标题（不确定就不给），
   再依次在论文库、OpenAlex、Semantic Scholar（常被限流，只在 OpenAlex 出错时用）里核对。**宁缺毋滥**：
   - 原论文不晚于对比它的论文里最早 20% 的时间 + 30 天；
   - 给了标题：标题一致或冒号前一致；改过标题的，要摘要里写明提出了这个名字且标题词大体重合（只是提到它的后续工作不算）；
   - 没给标题：标题必须以"方法名:"开头且有 arXiv 号。
   进库（标 backfill，不进每日精选）走相关性判定与速读；原论文不属于方向的列为"常被对比的邻近方向方法"。
   模型的判断马上落盘；查询出错（限流）时停下、下次接着查，不记成"找不到"；找不到的 30 天后再试；每次最多问 40 个。
   规则有版本号，规则变了旧结果重新核对，认错的去掉标记。
   （试做时出过的错：MoA 被认成同名的角色扮演论文、GEPA 被认成拿它当 baseline 的 Combee、ACE 被认成 2026 年的同名论文、
   OpenClaw 被认成一条 Zenodo 记录；都有单元测试。）
4. **梳理**：批量模型把经典分成 4–8 条技术路线，写主线、每篇的角色 / 贡献 / 为什么经典、建议先读的 8–12 篇；只能引用给出的 id（编出来的去掉）。
   被对比数、引用数、它对比过的更早经典、后来和它比的工作、常用 benchmark 上的成绩、代码状态都由工作台从论文库和结果表算。
5. **不过口味过滤**：经典是参照，不是推荐。AgentPrune、AgentDropout 这类以省 token 为主的工作不合本人口味，但它们是必须比的 baseline。
6. 每日流程的"报告"一步刷新事实；路线划分在经典集合有变化或满 7 天时重做（`wb classics build --fresh` 强制）。
   面板新增"经典"页，CLI `wb classics build | ls`，数据在 `reports/classics.json`。

## 后果
- 论文库会多出一批被大量对比的方法的原论文（大多是 2023–2024 年的），结果表、地图、必读也因此更完整。
- 影响力依赖论文库里的对比关系：近 12 个月是全量收录，更早的只有顶会论文和找原论文进来的，所以"被对比数"反映的是近期论文的引用习惯。
- 新方法要积累到 8 篇对比才算经典，新进的先放"新进的经典"组，下次梳理时归类。
