# ADR-0023：复现 = 先按原文设定跑通并对上数字，再上自己的设定

- 状态：已接受
- 日期：2026-10-11

## 决策
1. 官方代码拉到 `<baseline_dir>/<论文>/`（沿用 AFlow / MaAS 的惯例），环境放在该目录自己的 `.venv`。
2. **先跑原文设定**（同任务 / backbone / 种子），守护进程自动抓现场；认领到 baseline 配置组（如 `maas-gsm8k-paper`），
   配置组上记录**论文报告的数字**作为参照。
3. **完成标准**：与论文数字的差距在容差内（默认 ≤ 2 个点，或在论文报告的标准差内）。
   达不到就标 **"复现差距"** 并记录原因（原因本身常常就是一个问题 Problem，ADR-0018）。
4. 之后才跑**自己的设定**（自己的 backbone / 任务），作为另外的配置组，可挂进自己论文的 claim。

## 后果
- 配置组需要新字段：`paper`（关联论文）、`reported`（论文报告的指标）、`repro_status`（未开始 / 进行中 / 已复现 / 复现差距）。
- 面板配置组页并排显示"论文报告 vs 我们复现（均值 ± 标准差）"。
