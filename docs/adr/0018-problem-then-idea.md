# ADR-0018：先有"问题"，再有 IDEA；都用真实例子说话

- 状态：已接受
- 日期：2026-10-11

## 决策
两层结构：

1. **问题 Problem**：现有方法做不好的一件具体的事。来源只有两种：
   - **聚合多篇论文**发现的共性问题（证据 = 这些论文里的原文、表格数字、图）；
   - **分析 bad case** 定位出的问题（证据 = 工作台里某些 Run 的逐样本输出，ADR-0008）。
   每个问题一个 **HTML 文件**，配图说明；**图必须由真实例子画成，不可以猜**
   （真实的轨迹 / 样本 / 论文里的数字），每张图注明数据来自哪篇论文的哪张表、或哪个 Run 的哪个样本。
2. **IDEA**：针对某个问题的解决方式（一个问题可以有多个 IDEA）。
   - 状态：记录 → 验证中（有探索 Run）→ 升级为 claim（进入论文项目）/ 放弃（写明原因，不删）。
   - 每个 IDEA 按 **paper-explainer** skill 写成 HTML，**只写前 6 步**：
     动机 → 现有工作分类 → 现有工作的问题（配图）→ 根因 → 最直接解法 → Idea 实现细节（框架图 + 公式逐项解释）。
     Claims 与实验设计**不写进 IDEA 文档**，它们在论文项目页里（claim → 配置组 → Run，ADR-0010），IDEA 升级为 claim 时建立链接。
   - Step 3–4（问题、根因）直接引用对应 Problem 文档里的真实例子。

## 来源
paper-explainer 以 `作者本地 skill 库中的 paper-explainer`（2026-10-09 23:02 版，含"排版硬性规则"）为准；
要在实验室服务器的 codex / Claude 里可用，需要随工作台一起部署（与 record-experiment 同样的链接方式）。

## 后果
- 逐样本输出（jsonl + 稳定 sample_id）从"可选"变成 bad case 分析的前提，agent 启动实验时应尽量让实验写出逐样本结果。
- 整条链：论文 → 问题 → IDEA → 验证 Run → claim → 论文项目。

> 2026-10-11 补充：问题与 IDEA 的产生节奏、筛选与保留见 ADR-0024（每天主动想，评估后只告诉够 CCF-A 的）。
