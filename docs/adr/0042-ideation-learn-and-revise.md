# ADR-0042：构思从被拒中学习，接近通过的修改一轮再评

- 状态：已接受（补充 ADR-0018 / 0024）
- 日期：2026-10-14

## 背景
本人问 IDEA 什么时候开始。实际上构思从 10-12 起每天都在跑（每天 4 个候选 + 独立审稿），到 10-14 共 16 个候选、0 个通过；
IDEA 页面却显示"论文库积累到一定规模后才会开始构思"，是错的。被拒原因（审稿意见本身合理）：
新颖性一票否决最多（核心机制已被 Hetero-Designer、AutoMaAS、From Spark to Fire 等覆盖）；深度不够（数学对象、损失、训练机制没定义）；
证据错误（公式编号、数字对不上，触发问题真实性否决）；实验超预算。最接近的 3 个均分 6.25–6.5、没被否决。

问题在流程：每个候选只有一次机会；构思时也不知道以前为什么被拒，反复撞车、反复不够具体。

## 决策
1. **从被拒中学习**：构思材料里加 past_reviews.json（最近 40 个被拒候选：撞了哪些已有工作、证据错在哪、主要弱点），
   提示里写明以往被拒的四类原因和对应要求（提交前找 ≥ 3 篇最接近工作并说清本质区别、定义数学对象与目标、逐字核对证据、实验在预算内）。
2. **修改一轮再评**：没有一票否决、均分 ≥ 6 的候选，作者（codex）按审稿意见改一轮（不准改问题证据，除非逐字核对过新证据），
   换一个审稿人重新评；以第二次评审为准。最多一轮。
3. **标准不放低**：仍是一票否决 + 均分 ≥ 7，并过口味过滤；没通过的不推送。
4. **IDEA 页面**：去掉错误的提示，显示构思记录（每天候选数、通过、否决、因额度没评成）和"最接近通过的"（折叠，带审稿总评与四项分数）。

## 后果
- 每天多 0–4 次 codex 调用（修改 + 重评，只针对接近通过的候选）。
- 被拒的候选仍不推送；页面上折叠显示只是让本人知道构思在进行、卡在哪里。
