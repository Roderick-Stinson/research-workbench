# ADR-0041：领域地图改成"发展史 / 热点变化 / 评测与基线 / 空白与发现"

- 状态：已接受（修改 ADR-0021 的展示）
- 日期：2026-10-14

## 背景
本人反馈：地图每一类只是罗列全部论文（一类最多 130 篇），基本不可读。需要能看出：1. 发展史；2. 研究热点的变化趋势；3. 其它没想到、但对研究有帮助的东西。
另外地图是 10-12 用 472 篇论文生成的，之后论文库扩到约 2,600 篇（含 2023 年以来的顶会论文）。

## 决策
1. **研究主题**（`themes.py`）：维度标签太粗，看不出热点。由批量模型从按时间分层抽样的论文里提出 12–20 个具体主题（存 registry/themes.json，可改），
   再给每篇属于方向的论文打 1–2 个主题；新论文每天增量打，主题表每 30 天重新提议（保留稳定的 id）。
2. **统计**（`mapview.py`，全部可复核）：
   - 热点：各主题按半年的占比（不是篇数——论文库近 12 个月全量、更早只有顶会顶刊论文，篇数会被采样偏差带偏），近半年 vs 再往前半年的变化；早期样本少的时间段单独标注；
   - 搜索方式、粒度的占比变化；
   - 评测与基线：近 12 个月方法论文最常比的领域常用方法（"现在要比的 baseline"）、每年最常用的 benchmark 与 baseline、常用 benchmark 每半年的最高报告分（看饱和）；
   - 空白：研究主题 × 搜索方式的篇数矩阵（近 12 个月）。
3. **叙述**（批量模型，每周一次）：依据里程碑论文（必读清单 + 领域常用方法原论文，带"对比过哪些更早的里程碑"）和上面的统计，
   写发展阶段（主线、转折、里程碑及一句话）、变化最明显的主题的解读、4–7 条"其它发现"（必须比的 baseline、接近饱和的 benchmark、少有人做的组合、
   有争议的结论、评测的通行做法与陷阱……），每条都要有论文或统计依据；编出来的论文 id 会被去掉。
4. **页面**：概述 → 发展史（时间线）→ 热点变化（每个主题一行：占比、变化、小折线、解读）→ 评测与基线 → 空白与其它发现 → 分类
   （原来的主分类只留核心思路、没考虑到什么、代表工作，不再罗列全部成员）。

## 后果
- 每天多几次小的批量模型调用（新论文打主题），每周一次写叙述；第一次要给全部论文打主题（约 70 次调用，回填预算）。
- 早期（2023–2024）每个时间段只有十几篇顶会论文，那几段的占比只能作参考；页面上明确标出。
