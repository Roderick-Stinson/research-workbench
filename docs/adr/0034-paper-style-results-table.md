# ADR-0034：结果表改成论文式：按任务分类、标出评测规模

- 状态：已接受
- 日期：2026-10-12

## 背景
旧的结果表是"一个 benchmark 一页、按 指标 × backbone 分组的长列表"，本人反馈三点：
1. 数据集要按类别分（数学 / 代码生成 / 问答……）；
2. 有的方法在完整数据集上评测，有的只在随机抽样的子集上评测，必须突出显示；
3. 读起来累，希望像论文主表一样：同一数据集、同一指标下，不同方法并排对比。

另外原始数据里同一个数据集有很多写法（共 1,378 个名字，含 "Avg." 这类非数据集），指标（Acc / Accuracy / Solve Rate）、
backbone（GPT-4o-mini / gpt-4o-mini-2024-07-18）、方法名（CoT-SC / CoT SC (5-shots)）也都没有归一。

## 决策
1. **数据集归一与分类**（`workbench/papers/datasets.py`）：常见数据集写在 `KNOWN` 里（含确定的官方全量规模）；
   其余名字由批量模型归类一次，存 `registry/datasets.json`，以后只归类新出现的名字。同一数据集的写法合并，
   不同版本 / 年份 / 子集分开（AIME 2024 ≠ AIME 2025，MATH ≠ MATH-500）；平均 / 总体行标为 aggregate，不进表。
2. **评测规模从原文抽取**：每篇论文、每个数据集记 划分 / 实际题数 / 全量还是抽样或子集 / 怎么选的 / 出处。
   新论文在速读里一起抽（`eval_sets` 字段，不多花一次调用）；老论文由 `datasets.fill()` 补，只看全文里提到数据集与评测设置的段落，
   受回填预算约束，每 30 分钟的 `wb daily resume` 每次补 80 篇。原文没写就是"未注明"，不用模型自己的知识补。
   判定：原文说抽样 / 子集，或题数小于全量 → 子集；原文说完整划分，或题数不小于全量 → 全量；否则未注明。
3. **论文式对比表**：分类 → backbone → 表，行 = 方法，列 = 数据集 · 指标；每列最好加粗、第二下划线；
   子集的格子带橙色题数标记，未注明的带 "?"；表头写官方全量规模，同一列混有不同规模时标"规模不一"；
   表下列出每一列各论文用的评测设置。点列名进入单个数据集视图：行 = 方法，列 = backbone。
   同一方法在同一格有多处报告时，优先它自己的论文，其次全量评测，再次最新的论文，其余放在悬停提示里。
   可切换：效果 / 成本、只看全量评测、显示消融、含只有一篇论文报告的数据集。
4. 指标、backbone、方法名做轻量规则归一（原始写法保留在悬停提示里）；唯一改动数字的地方是同一列大多为百分数而某条写成 0.xx 时乘 100，并注明。
5. 每日流程新增 `results` 步骤（速读之后）：归类新数据集名、补当期论文的评测规模、重建 `reports/results_index.json`；面板读这个索引。
6. 种子论文本身也进论文库（之前只用来追踪引用，导致 ADAS、G-Designer 等基线的原文数字不在结果表里）。

## 后果
- 跨论文的数字仍然只能作参考：提示词、采样次数、划分都可能不同。评测规模是最常见的不可比原因，现在能一眼看出来。
- 规则归一可能把少数不同的东西合并（例如 code 类里的 Accuracy 视为 Pass@1）；原始写法在提示里可以核对。
