# ADR-0045：复现在面板上看得到；在别的电脑上启动的实验补关联对话

- 状态：已接受
- 日期：2026-10-19

## 背景
本人问：一次论文主实验复现的 session 里的实验，为什么没记录到工作台？
核查：实验都记了——3 个配置组（直答 baseline、发布权重、未训练 orchestrator）、11 个认领的 Run、指标、`wb repro ref` 记下的论文数字、
配置组备注里的复现差距分析。看不到的原因有两个：
1. 面板首页只列"项目"和"待认领"。按 CONTEXT.md 的约定，复现别人的论文不建项目（项目只是本人自己的论文），
   这些配置组没挂到任何 claim 上，认领之后在面板上没有入口；论文页也不显示它的复现结果。
2. 那个 session 是本人 Mac 上的 Claude，通过 `ssh` 在服务器上启动实验。守护进程只读服务器上的对话记录，
   所有 Run 的"对话"都是空的（`session: None`）。

## 决策
1. **首页"复现"栏**：列出所有没挂到项目上的配置组，按关联的论文分组；每个显示 Run 数、复现状态、几项在容差内、差得最多的几项。
2. **论文页"我们的复现"**：关联到这篇论文的配置组，论文数字和我们的均值 ± 标准差逐项并排。
3. **复现状态**：还有 Run 在跑是"进行中"；否则只看跑了的指标——全部在容差内"已复现"，否则"复现差距"。
   论文报告了、但我们没跑的指标单独注明，不影响判断（之前有一项没跑就一直是"进行中"）。
4. **`wb session attach <RUN>...`**：从 stdin（或 `--file`）读一份 codex / Claude Code 对话记录，存进数据目录的 `sessions/`（权限 600），
   在这一份记录里给每个 Run 找启动它的调用，写进 claim.json 的 `session`（守护进程的 run.json 不动）；读 Run 时，
   守护进程没关联到对话就用这个。`wb adopt` 发现 Run 没关联到对话时提示这条命令；agent 规则和 skill 写明。
5. **匹配更准**（守护进程平时的自动关联也用同一套）：通过脚本启动时，命令文本里没有 python 的参数，按文本相似度会输给更早的同参数试跑。
   现在：启动前 2 分钟内、命令里写了 Run 目录、看起来像启动命令（nohup / .sh / python / 后台 &）的调用优先，取离启动最近的；
   启动之后的调用（两台机器时钟差几秒才会出现）排在启动之前的后面；启动前 5 分钟内的调用加分。

## 后果
- 复现别人的论文仍然不建项目，但在首页和论文页都看得到。
- 对话记录会复制一份到服务器的数据目录（只在 agent 执行 `wb session attach` 时）；面板显示时照常脱敏。
- 在那次复现上验证：27 个 Run 全部关联到启动它们的调用，每个都在启动前 2–20 秒。
