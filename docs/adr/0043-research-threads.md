# ADR-0043：研究线——少而深、持续推进的构思

- 状态：已接受（取代"每天从零构思 4 个"的做法；广撒网构思改为每周一次）
- 日期：2026-10-14

## 背景
本人质疑"是不是根据每天的论文推荐来想 IDEA"。核查：不是——构思读的是整个论文库（2,614 篇的一句话 + 可读全文）、地图、问题、以往候选和实验记录；
16 个候选的 33 条证据没有一条来自每日精选。但做法确实不合理：每天从零开始想 4 个，有希望的方向不会被继续深挖；
没有锚定本人自己的研究（工作台里没有登记项目和 Run，bad case 来源实际是空的）；读的是 2,600 篇论文的一句话，深度不够。
本人选择：来源 = 自己的研究问题 + 复现与 bad case + 领域开放问题 + 保留广撒网；节奏 = 少而深，持续推进。
另外发现本人的复现与自己的方法（Ours 及消融）结果都在 /data2/wzh/baseline/results（逐样本 predictions.jsonl + 评测），工作台此前没用上。

## 决策
1. **研究线**（`threads.py`）：一条线 = 一个具体问题，同时最多推进 3 条（`ideation.max_active_threads`）。
   每天由 codex 推进一步：从 next_steps 和审稿意见里挑最有价值的一件事做扎实（精读关键论文、联网查新、读逐样本预测归纳失败模式、
   形式化方法、设计预算内的最小实验、按意见改草稿），发现带出处记在线上；草稿满足"证据逐条核对、≥ 3 篇最接近工作说清区别、方法形式化、实验在预算内"才交审稿。
2. **审稿**：沿用独立审稿与标准（一票否决 + 均分 ≥ 7）+ 口味过滤；通过 → 正式 IDEA 并告知；没通过 → 意见进下一步；审稿 3 次仍不过 → 搁置并写原因。
   codex 也可以判断这条线走不通（问题不真实、已被解决、证据推翻假设）而主动搁置。
3. **来源与优先级**：本人的研究问题（`wb thread add "问题" --mine`，可附工作区 / 结果目录）> 复现与 bad case（配置的结果目录里有逐样本预测时自动建一条）
   > 领域开放问题（以往接近通过的候选优先——它们已有审稿意见可以接着改）。本人的工作区（`baseline_dir` 的上一级）对 mine / repro 线可读。
4. **广撒网构思**（ideate.run）改为每周一次（`ideation.scout_weekday`，默认周一），接近通过的进研究线候选。
5. **告知**：只在有实质进展时推送（新线开始、审稿结果、通过成为 IDEA、搁置）；每天的研究记录在 IDEA 页面上看。

## 后果
- 每天 codex 调用 ≈ 活跃线数（3）+ 偶尔的审稿；比原来每天 1 次构思 + 4 次审稿 + 修改更省，也更深。
- 本人自己的研究问题需要本人说出来；没说之前，研究线来自复现结果和以往接近通过的候选。
